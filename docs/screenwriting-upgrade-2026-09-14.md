# 鲲鹏编剧与文案能力审阅（2026-09-14）

## 结论与原有问题

原有文案工作室已包含广告导演、剧本医生和反模板表达指导，但主要依靠一句任务关键词选择提示词。普通对话的系统提示没有同等编剧方法；文风审校按正则匹配措辞，无法判断人物行动、因果或情感效果。剧本医生入口虽说不强制模板，后文仍将固定页码、三幕比例和救猫咪节拍覆盖率作为量化指标，存在内部冲突。

最具体的误伤：正常对白“不是我不让你走，是……”会触发 blocker；重复出现三次的“钥匙”会被当成重复比喻；用户可能为了提高机械分数删掉人物的表达或道具伏笔。

## 查阅资料与取舍

- [screenwriting-skills](https://github.com/jtydhr88/screenwriting-skills)，快照 `560237cd280cafb96d15d2cf3a71ff6a8ce47756`。阅读工作流、对白、故事结构与剧集设计等入口，借鉴按创作阶段组织任务、区分媒介和维护长期创作状态的思路。仓库标明仅供个人学习，未将其书籍摘录、范例或整套技能复制进产品；以下为结合项目问题独立编写的实现。
- [山音超级编剧大师](https://github.com/Shanyin-ai/shanyin-screenwriting-master)，快照 `ca20ce245ae028e64418393d6cf4688b7dbe3d89`，MIT。用户提到的“超级编辑大师”对应此编剧项目。阅读集成版中格式路由、视听叙事、自检、时长与连续性管理方法；按鲲鹏交互方式重新组织，不引入每个阶段强制等待批准的工作流。
- [Academy Nicholl 的公开评审维度](https://www.oscars.org/nicholl/about)：关注故事、独特声线、人物、技法与意义。用作审阅视角，不代表学院认证或统一行业打分标准。本次不涉及比赛规则更新。
- [John August：How to write a scene](https://johnaugust.com/2007/write-scene)：先判断场景对整体的必要性，再考虑人物、地点和进入方式；将场景功能与角色目标同时纳入检查。
- [Sundance Collab：Robin Swicord 的改编课程公开介绍](https://collab.sundance.org/catalog/Writing-Screenplay-Adaptations)：核对改编核心、人物、故事驱动力等方向。只阅读公开介绍，未声称购买或阅读付费课程内容。

没有把“好莱坞编剧”当作单一公式。三幕、救猫咪、英雄之旅可以提供观察角度，生活流、群像、非线性和开放结尾需要按作品自身承诺判断。原有理论资料继续保留，按需阅读。

## 已实现

1. `screenwritingCraft.ts` 集中维护编剧指导，并接入普通对话系统提示和文案任务提示。覆盖创意、人物、场景、对白、信息分配、长短片/剧集差异、改编边界、长稿状态和修订检查。
2. 文案工作室新增“剧情审阅”，向现有写作对话发起只读审稿请求。审稿默认不改正文，明确要求改稿后才修改。
3. `copywriting_review_doc` 增加 `mode=story`，返回原文、块编号、块哈希、位置、文档版本及审阅问题。每页最多约一万字符，提供 `nextStart`。后续分页要求 `content_revision`，防止混读版本；极长单段也能连续读完。工具不额外调用另一个模型，不伪造剧情评分，语义审阅由当前模型完成。
4. 保留原有 `mode=style` 兼容性。检测为剧本时，词频/标点结果降为需结合语境判断的线索，不触发强制改稿；支持中文数字场号及 Fountain 正文检查。通用商业文案保留原有规则。
5. 剧本医生升级至 3.0.0，精简冲突规则和固定评分模板，改为原文证据、观众影响、根因、最小修改与影响范围。本机已安装技能也同步更新并备份。个人视频脚本技能保留既有声线，补充语境例外与事实边界。

长稿“创作档案”属于编剧工作流要求，借助现有读写工具保存；本次没有新增独立故事数据库，也没有训练或替换模型权重。

## 实际试写与限制

使用合成素材调用 DeepSeek Flash，最后一轮开启 thinking，与 DSH 的思考开关一致。保存最终回复、输入和用量，未保存推理正文或凭证。结果见 `evals/screenwriting-flash-2026-09-14.json`。这是直接模型试写，不冒充 DSH/UI 端到端测试，也不是盲测或能力提升百分比证明。

首次低思考成本试写暴露出：短场景超长、把手上没拿东西误认成没有持有道具、生活流提案加入用户排除的倒计时。随后补充交付约束、状态区分与根因合并，并以新道具题复测。

最终人工复核（由本次开发助手进行）：

- 剧集提案：保留六集、修鞋摊、父女关系与开放结尾，未再添加截止日或重大病情；仍有抽象“局部回报”，需要进一步发展为事件。
- 连续性审阅：抓到唯一钥匙的交接断点，引用原文且没有写回正文；但仍过度解读“两手空空”和“门锁坏了”，有硬凑第三条的倾向。不能将所有建议视为已证实缺陷。
- 一分钟场景：能写出行为与回避，但对白/动作总量仍偏长；没有经过演员计时，不能标为一分钟验收通过。
- 新道具题：没有硬凑三个问题，能指出背包是否随身属于未知；但先称确定矛盾、后承认条件不足，结论不够稳健。

因此，工程验证通过，创作试写并非全部通过。当前 Flash 的语义判断和长度控制仍需要创作者复核。此次采用只读审阅、原文可追溯及禁用剧本自动机械改稿，降低错误建议直接破坏正文的风险；后续可用这组固定素材继续比较模型和修订策略。
